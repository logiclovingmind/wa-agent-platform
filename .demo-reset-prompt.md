Build the demo reset button. Read the session-28 entry in the project memory first for
the background; the short version is that a walk-in demo overlays a prospect's business
onto the demo org, and this is the one-click undo.

## 1. Migration `supabase/migrations/0026_demo_reset.sql`

`public.demo_reset()`, `security definer`, `set search_path = public`.

- First statement in the body is the guard: `if not app.is_platform_admin() then raise
  exception ... end if;` — same shape as `admin_orgs()` in 0012.
- It deletes only what a walk-in *added*, so the seeded backdrop is never rebuilt:
  - `conversations` where `customer_wa_id not like '9199900%'`
  - `kb_documents` where `title not like 'Demo — %'`
  - `usage_events` where `pricing_category <> 'demo_reply'`
- Every one of those is scoped by **two locks**, exactly like the deletes at the top of
  `scripts/demo-seed.sql`: `org_id = (select org_id from wa_accounts order by created_at
  limit 1)` AND `org_id in (select id from organizations where is_demo)`.
- Then restores the org: `name = 'Demo Institute'`, `sector = 'general'`, `voice =
  'warm and unhurried; explains before it sells; mirrors the customer''s Hinglish'`,
  `reply_max_words = 120`, `languages = 'English, Hindi, Kannada'`.
- Returns something the UI can show — a count of rows removed is fine.

Then the permissions, which are NOT optional:

```sql
revoke all on function public.demo_reset() from public, anon;
grant execute on function public.demo_reset() to authenticated;
```

`anon` must be named explicitly. Supabase grants EXECUTE on every new `public` function
to `anon` and `authenticated` by name, so `revoke ... from public` alone leaves it
callable by anyone holding the publishable key — which is compiled into the dashboard
bundle. This exact mistake has shipped four times in this repo (0006/0007, 0015, 0016,
0017). The in-body admin guard is not a substitute; the rule is two locks.

## 2. `scripts/demo-seed.sql`

Replace the tail `update organizations set name = ... languages = ...` (the one just
above `commit;`) with `select demo_reset();`, so the default identity is defined in one
place. At that point in the file every conversation is `9199900%` and every KB doc is
`Demo — %`, so the deletes inside it are no-ops and only the restore runs.

Careful: the seed runs as the migration workflow's superuser, not as a platform admin,
so the `app.is_platform_admin()` guard will refuse. Either make the guard accept a
superuser/`service_role` caller, or keep the seed's update and accept the duplication —
your call, but say which you chose and why.

## 3. `dashboard/src/Admin.tsx`

A "Reset demo" button on the demo org's row (the one with `is_demo`), visible to the
platform admin only. Two-click confirm, same pattern as the erase button in the inbox.
It calls `supabase.rpc('demo_reset')` directly — no Worker route, because the RPC is
definer and the admin account holds no `org_members` row. Show the row count on success
and the error on failure; do not swallow the error.

## 4. `scripts/ship.sh`

Add `check_anon demo_reset '{}'` next to the three existing checks (~line 112).
`demo_reset()` takes no arguments so `{}` resolves correctly; it must answer `42501`.
